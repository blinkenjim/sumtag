# To-do

Deferred features and design decisions raised in conversation, not yet built. See BUGS.md for known defects, and CLAUDE.md's "Future work" section for design-level future work already documented there (alternate digests' storage shape, network database backends, a `runs` table, stale-row pruning/dedup/audit tooling).

- **`--digest` flag for selectable algorithms.** `xxh3` is the documented default (CLAUDE.md "Extended attribute schema"); `sumtag/hashing.py` already supports `md5` alongside it, selected today by hand-editing `schema.ALGO` (a temporary code-level switch, previously used for cross-checking against `md5sum`; `scripts/xxh3_crosscheck.py` now checks the real `xxh3` default directly via `xxhsum -H3`, so the switch is no longer needed for routine testing). A real `--digest` CLI flag should make the algorithm selectable at the command line, defaulting to `xxh3`, without requiring a source edit.

  Design resolved 2026-07-02 (see CLAUDE.md "Digest container", "Re-hashing logic", and Database storage's Schema section for the full writeup): the xattr's `digests` map holds exactly one entry, ever — never accumulates multiple algorithms simultaneously. Freshness is algorithm-agnostic (any current digest counts as up to date; switching the active algorithm never forces a re-hash by itself, which matters at TB scale). When a file does get re-hashed for any of the normal reasons, it computes under whichever algorithm is currently active and *replaces* the single stored digest. Deliberately re-stamping a whole archive under a new algorithm is `--force` (once `--digest` exists), same mechanism as today. Known consequence: dedup queries (`GROUP BY algo, digest`) won't find duplicates across files stamped under different algorithms — a documented hazard, left to higher-level dedup tooling to detect and warn about, not something sumtag itself needs to solve.

- **`--exclude` flag (path/glob exclusion at scan time).** Explicitly low priority — floated once "in case it's ever wanted," not because it's blocking anything. Would complement the existing `@sumtag-ignore` marker mechanism (which requires dropping a file into a directory) with a command-line way to exclude paths/patterns without touching the filesystem. No design done yet: syntax (glob vs regex), single vs repeatable flag, and interaction with `@sumtag-ignore`/`--no-ignore` are all undecided.

- **Handle SIGWINCH (terminal resize).** Two uses: (1) resize `--progress`'s bar to fill the new terminal width — already anticipated in CLAUDE.md's "`--progress` indicator" section, which notes the bar is the one field designed to flex while every other field stays fixed-width; (2) truncate the ends of very long lines (e.g. long paths in per-file announcements) so they don't wrap the terminal, for a cleaner look. No design/implementation done yet — open questions include where truncation happens (start/middle/end of the path), whether it applies to every announcement or just certain ones, and how it interacts with `--prescan`'s prefix and `-v`'s longer lines.

- **Extend the conformance harness to the newer features.** Noted 2026-07-02 after a clean harness run (17/17): the scenario catalog (`tests/harness/scenarios.py`) covers stamping/skip/re-hash decisions, `--force`, `--verify`'s two corruption-table cases (silent corruption → exit 1, legit edit → exit 0), ignore markers, dry-run, and the database modes (`--sum`, `--import`, `--locate`) — but has no scenarios for `--remove` (including its `-n` preview and its conflicts with `--database`/`--verify`/`--force`), `--prescan` (counter prefix, mode-mirroring of what gets counted, the `--remove` conflict), `--verify`'s `unverifiable` case and exit code 2 (errors preventing a complete check), or `--no-ignore`. Worth adding so the harness tracks the full documented surface in CLAUDE.md.

- **Require an explicit directory argument; drop the cwd default.** Requested 2026-07-02, motivated by safety: defaulting a bare `sumtag --remove` (or any other recursive command) to the current directory makes it too easy to run a destructive/recursive operation against the wrong tree by omission. Recommendation (discussed, not yet decided as final): apply this uniformly to every subcommand rather than singling out `--remove` — a rule that only applies to some flags is harder to internalize than one that always applies, and the cost (typing `.` explicitly) is trivial. Implementation would change `directories` from `nargs="*"` to `nargs="+"` in `cli.py`, and update every "with no directory arguments, cwd is processed" reference in CLAUDE.md, both man pages, and the `sumtag` (no args) example throughout. This is a breaking CLI change for anyone currently relying on the bare `sumtag` invocation.
